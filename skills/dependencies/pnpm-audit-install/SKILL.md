# pnpm Audit Install

Every new package passes an [npq](https://github.com/lirantal/npq) audit before `pnpm add` touches `package.json`. npq only audits; pnpm does the install.

## Workflow

### 1. Audit

One package per run, so a failure is isolated to its package:

```bash
pnpm dlx npq install <pkg>[@<version>] --dry-run --disable-auto-continue
```

`--dry-run` keeps npq read-only; `--disable-auto-continue` stops it auto-proceeding past warnings. npq checks Snyk CVEs, typosquatting, install scripts, age, downloads, license, repo, signatures, provenance, and deprecation.

Sort each package into `SAFE` or `BLOCKED` (with the reason). **Hard block**: any Snyk CVE or typosquatting warning. Suggest an alternative package for each blocked one.

Audit-only request? Report the `SAFE` / `BLOCKED` split and stop here.

### 2. Confirm

Show the split and get the user's approval to install the `SAFE` list.

### 3. Install

```bash
pnpm add <pkg>...        # dependencies
pnpm add -D <pkg>...     # devDependencies
pnpm add <pkg> --filter <workspace>   # one package of a monorepo
```

Done when every approved package is in `package.json`, `pnpm-lock.yaml` is regenerated by pnpm, and `pnpm audit` reports no new advisories.

**Install-script gate**: pnpm 10+ skips dependency lifecycle scripts unless the package is allow-listed (`onlyBuiltDependencies` / `pnpm approve-builds`). When pnpm reports ignored build scripts, show the package names to the user and let them decide; approving one runs its code on this machine.

## Environment variables

| Variable | Purpose |
|---|---|
| `SNYK_TOKEN` | Enables the Snyk vulnerability DB (recommended) |
| `GITHUB_TOKEN` | Raises GitHub API rate limits |

For bulk updates of existing dependencies, use the `pnpm-audit-update` skill.
